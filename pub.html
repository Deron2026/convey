立刻行动点：现在就去 claude.ai 把模型切换成 Opus 4.8，输入一个你之前没解决的 Bug 代码，看它是否直接指出问题。

深度分析

快速上手路径：5分钟跑通第一个profiler

新闻给出了最低门槛操作：复制01matmuladd.py脚本，在GPU机器上运行uv run 01matmuladd.py --size 64，就能立刻得到两个文件：profiler table (.txt)和trace (.json)。核心步骤只有4步：①用torch.profiler.recordfunction标注自定义函数；②将代码包裹进torch.profiler.profile上下文管理器；③设置prof.step()循环；④通过prof.keyaverages().table()和prof.exportchrometrace()导出结果。

立刻行动点：打开你的PyTorch项目，找一个最慢的GPU运算函数，按上述4步插入profiler代码，直接运行看看CPU/GPU时间占比。

典型使用场景举例：从训练到推理的瓶颈定位

新闻以矩阵乘法+加法作为起点，展示了如何通过profiler发现overhead-bound（GPU利用率低）或compute-bound。同样的方法可直接扩展到三个场景：

  • 训练循环优化：用profiler包裹整个step，观察aten::matmul和amperebf16s16816gemm...等kernel耗时，找出热点；
  • 推理延迟优化：对model.forward()添加record_function，对比不同batch size下CPU调度时间与GPU计算时间的比例；
  • torch.compile效果验证：新闻后续会对比编译前后的trace变化，你可以立即在自己的模型上做同样对比。

立刻行动点：用torch.profiler.record_function包裹你模型中最大的矩阵乘法模块，直接看Self CUDA time total是否远小于Self CPU time total，如果是，说明需要增大计算量或合并算子。

新手最容易遇到的问题与解决办法：读不懂trace？先看两个数字

新闻指出profiler上手难的核心是trace中密集的彩色矩形和复杂事件名。新手最容易犯的错误是直接钻进trace细节，反而抓不住重点。新闻给出了两个最直接的入门方法：

  • 先看profiler table的最后两行：对比Self CPU time total和Self CUDA time total的单位和数值。如果GPU时间只有CPU时间的<1%，就是overhead-bound，立即增大矩阵尺寸；如果两者在同一量级，就是compute-bound，可以深入看kernel具体耗时。
  • 在Perfetto UI中用WASD键导航（新闻建议），先看CPU lane和GPU lane之间的空档（idle时间），空档大表示CPU调度慢，而非GPU不够快。

立刻行动点：运行uv run 01matmuladd.py --size 64后打开.txt文件，只看最后一行Self CUDA time total和倒数第二行Self CPU time total，计算比例。
